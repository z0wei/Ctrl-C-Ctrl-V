## 1. Основы

**Контроль доступа** — ограничения на то, **кто** и **что** может делать в приложении.

Стоит на трёх столпах:

| Механизм | Вопрос |
|---|---|
| **Аутентификация** | Кто ты? |
| **Управление сессиями** | Тот же ли ты, что и в прошлом запросе? |
| **Контроль доступа** | Можно ли тебе это делать? |

**Ключевая идея:** уязвимости контроля доступа — это **логические ошибки**, а не баги в коде. Приложение знает, кто ты, но не проверяет, **что тебе можно**.

---

## 2. Типы контроля доступа

| Тип | Суть | Пример нарушения |
|---|---|---|
| **Вертикальный** | Разные роли → разные функции | Юзер заходит в `/admin` |
| **Горизонтальный** | Одна роль → разные данные | `alice` видит заказы `bob` (IDOR) |
| **Контекстно-зависимый** | Доступ зависит от состояния/порядка | Можно пропустить шаг оформления заказа |

**Вертикальное нарушение** = повышение прав до админа.
**Горизонтальное нарушение** = доступ к чужим данным того же уровня.

## 3. Методология тестирования

Последовательность проверки любого эндпоинта:

```
1. Найти скрытую функциональность
   └→ robots.txt, sitemap.xml, JS-файлы, комментарии HTML, фаззинг путей

2. Проверить прямой доступ
   └→ Открыть /admin, /panel, /api/v1/users без авторизации

3. Проверить параметры и куки
   └→ role, isAdmin, admin, user_id, account, debug

4. Подменить ID объекта
   └→ id=1 → id=2, user=carlos → user=alice

5. Подменить HTTP-метод
   └→ POST → GET, PUT, PATCH, DELETE, OPTIONS, HEAD

6. Добавить платформенные заголовки
   └→ X-Original-URL, X-HTTP-Method-Override, X-Forwarded-For

7. Проверить несоответствия URL
   └→ регистр, суффиксы, слеши, кодирование

8. Проверить многошаговые процессы
   └→ пропустить шаги, отправить финальный запрос напрямую

9. Перехватить ответы с 302 / 401 / 403
   └→ в теле может быть утечка данных
```

**Инструменты:**
- **Burp Repeater** — ручная проверка каждого варианта.
- **Burp Intruder** — перебор ID, директорий, параметров.
- **ffuf / gobuster** — фаззинг путей.
- **Autorize** (расширение Burp) — автоматическая проверка прав.

## 4. Уязвимости: каталог

### 4.1 🔓 Незащищённая функциональность

Админ-панель доступна по прямому URL, но ссылка на неё скрыта из UI.

**Где искать URL:**
- `robots.txt`, `sitemap.xml`
- JavaScript-файлы (`/static/js/app.js`)
- HTML-комментарии (`<!-- admin panel at /admin-xyz -->`)
- Фаззинг: `/admin`, `/administrator`, `/panel`, `/manage`, `/console`

**Пример:**
```http
GET /admin HTTP/1.1
Host: site.com
→ 200 OK (панель без авторизации)
```

---

### 4.2 🎭 Безопасность через сокрытие (Security by Obscurity)

Админ-панель на «сложном» URL, но он раскрыт в клиентском коде.

**Пример:**
```javascript
if (isAdmin) {
    window.location.href = '/administrator-panel-yb556';
}
```

**Действие:** открыть DevTools → Sources → найти URL → перейти.

**Мораль:** сложный URL — не защита.

---

### 4.3 🍪 Контроль доступа через параметры

Роль пользователя хранится в **клиент-контролируемом** месте.

| Где | Пример | Что изменить |
|---|---|---|
| Кука | `roleid=1` | → `roleid=2` |
| Скрытое поле | `<input type="hidden" name="role" value="user">` | → `value="admin"` |
| Query-параметр | `?admin=false` | → `?admin=true` |
| JSON-тело | `{"role":"user"}` | → `{"role":"admin"}` |

**Типичные имена параметров:** `role`, `roleid`, `isAdmin`, `admin`, `user_type`, `access_level`, `debug`.

---

### 4.4 📨 Обход через платформенные заголовки

Фреймворки (Spring, Tomcat, Express) позволяют **переопределять** URL, метод или источник запроса через заголовки.

| Что подменяем | Заголовки |
|---|---|
| **Путь** | `X-Original-URL`, `X-Rewrite-URL`, `X-Original-URI` |
| **HTTP-метод** | `X-HTTP-Method-Override`, `X-HTTP-Method`, `X-Method-Override` |
| **IP-адрес** | `X-Forwarded-For`, `X-Real-IP`, `X-Client-IP` |
| **Хост** | `X-Forwarded-Host`, `X-Host` |
| **Протокол** | `X-Forwarded-Proto`, `Front-End-Https` |

**Пример подмены пути:**
```http
POST / HTTP/1.1
X-Original-URL: /admin/deleteUser
...
```
→ Валидатор проверяет `/` (разрешено), а бэкенд выполняет `/admin/deleteUser`.

**Пример подмены метода:**
```http
POST /admin/deleteUser HTTP/1.1
X-HTTP-Method-Override: GET
```

**Обход IP-ограничений:**
```http
GET /admin HTTP/1.1
X-Forwarded-For: 127.0.0.1
```

---

### 4.5 🔀 Обход через подмену HTTP-метода

Если защита настроена только на конкретный метод — пробуем остальные.

**Полный список методов для тестирования:**
```
GET, POST, PUT, PATCH, DELETE, OPTIONS, HEAD, TRACE
```

**Пример:**
- Заблокировано: `POST /admin/delete`
- Разрешено: `GET /admin/delete?username=carlos`

**В Burp:** правый клик → **Change request method**.

---

### 4.6 🧩 Обход через несоответствия в URL

Разные компоненты (прокси, фреймворк, приложение) по-разному парсят URL.

| Техника | Пример | Где работает |
|---|---|---|
| Регистр | `/ADMIN/DELETEUSER` | Spring, некоторые WAF |
| Суффикс | `/admin/deleteUser.anything` | Spring `useSuffixPatternMatch` |
| Слеш в конце | `/admin/deleteUser/` | Многие фреймворки |
| Двойное кодирование | `/%2561dmin` | Обход WAF |
| Точка в пути | `/admin/./deleteUser` | Нормализация |
| `..;` | `/admin/..;/admin/deleteUser` | Tomcat, Nginx |

**Стратегия:** перебери все варианты в Intruder, сортируй по Status code / Length.

---

### 4.7 🎯 IDOR (Insecure Direct Object Reference)

Подкатегория контроля доступа: приложение принимает **ID объекта** от клиента и не проверяет, принадлежит ли объект пользователю.

**Пример:**
```
GET /myaccount?id=123 HTTP/1.1
→ Профиль alice

GET /myaccount?id=124 HTTP/1.1
→ Профиль bob (IDOR)
```

**Типы идентификаторов:**

| Тип | Пример | Сложность перебора |
|---|---|---|
| Числовой | `id=123` | Легко (Intruder, Numbers) |
| Строковый | `user=carlos` | Легко (по словарю имён) |
| Хеш | `hash=abc123def456` | Трудно (нужен источник) |
| GUID | `guid=123e4567-e89b-...` | Практически невозможно |

**Где искать GUID / hash другого пользователя:**
- Комментарии, отзывы, форумы
- Публичные профили
- Ссылки на скачивание файлов
- Email-уведомления
- API-ответы (JSON, XML)
- Заказы и транзакции

**Автоматизация:**
```
Burp Intruder → Sniper → id=§1§ → Numbers 1–1000
Сортировать по Length / Status / grep по имени жертвы
```

---

### 4.8 📤 Утечка данных через редирект

Приложение возвращает **302 на /login**, но **тело ответа уже содержит данные**.

```http
HTTP/2 302 Found
Location: /login
Content-Length: 2048

<ul>
    <li>alice: alice@example.com</li>
    <li>carlos: carlos@example.com</li>
</ul>
```

**Действие:** в Burp **всегда смотри тело ответа**, даже если статус 302 / 401 / 403.

**Почему:** разработчик проверил права и сделал редирект, но **не очистил тело**.

---

### 4.9 🔗 Многоэтапные процессы

Проверка прав есть на первых шагах, но **отсутствует на финальном**.

**Пример:**
```
1. GET /admin/users        → 403 (проверка есть)
2. GET /admin/edit?user=x  → 403 (проверка есть)
3. POST /admin/update      → 200 (проверки НЕТ)
```

**Атака:** отправить **только шаг 3** напрямую, пропустив первые два.

**Как найти:** пройди процесс легально, зафиксируй **все** запросы, потом пробуй каждый в отдельности.

---

### 4.10 📎 Контроль доступа по Referer

Доступ к подстраницам проверяется по заголовку `Referer`.

**Обход:**
```http
GET /admin/deleteUser?username=carlos HTTP/1.1
Referer: https://site.com/admin
```

**Почему работает:** Referer полностью контролируется клиентом.

---

### 4.11 🌍 Контроль доступа по геолокации

Доступ ограничен по IP или стране.

**Обход:**
- VPN / прокси
- Подмена заголовков: `X-Forwarded-For: 127.0.0.1`, `X-Real-IP`, `X-Client-IP`
- `X-Country-Code: US`, `CF-IPCountry: US`

**Действие:** перебери заголовки в Intruder, смотри, меняется ли ответ.

## 5. Повышение привилегий

| Тип | Что происходит |
|---|---|
| **Вертикальное** | Юзер → админ (доступ к функциям выше) |
| **Горизонтальное** | Юзер A → данные юзера B |
| **Горизонтальное → вертикальное** | Через чужой аккаунт добраться до админа |

**Классическая цепочка:**

```
1. IDOR → находим ID администратора
2. Открываем его профиль
3. Сбрасываем пароль (если reset не защищён)
4. Логинимся как админ
```

**Ключевая идея:** горизонтальная уязвимость часто **открывает дверь** к вертикальной.

## 6. Сводная таблица payload'ов

| Уязвимость | Признак | Действие |
|---|---|---|
| **Unprotected functionality** | URL в robots.txt / JS / комментариях | Открыть напрямую |
| **Security by obscurity** | Сложный URL в JS | Найти в DevTools → открыть |
| **Параметры роли** | `role`, `isAdmin`, `admin` | Подменить значение |
| **X-Original-URL** | Валидатор проверяет `/` | Добавить заголовок с нужным путём |
| **X-HTTP-Method-Override** | Метод разрешён только через GET | Добавить заголовок `GET` |
| **IP-whitelist** | Доступ только с localhost | `X-Forwarded-For: 127.0.0.1` |
| **HTTP method** | POST заблокирован | Пробовать GET, PUT, PATCH, DELETE |
| **URL case** | `/admin` заблокирован | `/ADMIN`, `/Admin` |
| **URL suffix** | `/admin` заблокирован | `/admin.anything`, `/admin/` |
| **IDOR** | Параметр `id`, `user`, `account` | Перебрать значения |
| **Redirect leak** | 302 с телом | Смотреть тело ответа |
| **Multi-step** | Проверка на первых шагах | Отправить финальный запрос напрямую |
| **Referer-based** | Доступ по Referer | Подделать `Referer: /admin` |
| **Geo-based** | Блок по региону | VPN / `X-Forwarded-For` |

## 7. Защита: чек-лист

**Принципы:**
- ❌ Не полагаться на сокрытие URL
- ✅ Запрещать по умолчанию (deny by default)
- ✅ Единый механизм контроля доступа во всём приложении
- ✅ Явные разрешения для каждой роли на каждый ресурс
- ✅ Проверка прав на **каждом** запросе, а не только на входе

**Разработчикам:**

| Что делать | Чего избегать |
|---|---|
| Проверять права в **центре** (middleware, декоратор) | Проверок в контроллерах «по памяти» |
| Использовать ID сессии для идентификации пользователя | Доверять `user_id`, `role` из запроса |
| Проверять принадлежность объекта пользователю | Полагаться на «непредсказуемый» ID |
| Одинаковый ответ для «нет прав» и «нет ресурса» | Раскрывать существование ресурса через 403 vs 404 |
| Тестировать каждый эндпоинт отдельно | Считать, что UI скрывает = защищает |

## 8. Термины

| Термин | Значение |
|---|---|
| **Access control** | Ограничения на действия пользователя |
| **Vertical access control** | Разные роли → разные функции |
| **Horizontal access control** | Одна роль → разные данные |
| **IDOR** | Подмена ID для доступа к чужому объекту |
| **Privilege escalation** | Повышение привилегий |
| **Security by obscurity** | Защита через сокрытие (плохая практика) |
| **RBAC** | Контроль доступа на основе ролей |
| **Referer spoofing** | Подделка заголовка Referer |
| **GUID** | Глобально уникальный идентификатор |
| **Enumeration** | Перебор значений параметра |

## 🎯 TL;DR — что проверять первым делом

1. **Найди скрытые пути** — `robots.txt`, JS-файлы, комментарии.
2. **Открой /admin напрямую** — работает ли без авторизации?
3. **Подмени роль** — `role`, `isAdmin`, `admin` в куке / параметре / скрытом поле.
4. **Перебери ID** — `id=1`, `id=2` → чужой профиль (IDOR).
5. **Поменяй метод** — POST → GET / PUT / PATCH / DELETE.
6. **Добавь заголовки** — `X-Original-URL`, `X-HTTP-Method-Override`, `X-Forwarded-For`.
7. **Смотри тело 302/403** — там может быть утечка.
8. **Проверь финальный шаг** — многоэтапные процессы часто не защищены.
9. **Подделай Referer** — `Referer: /admin`.
10. **Всё в Intruder** — перебирай ID, пути, заголовки, методы.
